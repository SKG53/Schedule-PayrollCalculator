# FC-00009 — In-tool schedule OCR (paste screenshot → schedule)

**Date:** 2026-09-01 · **Slice:** M · **Risk:** Medium · **Status:** done · **Affected entities:** All

## What
On Tab 1 (Schedules), user pastes or uploads a schedule screenshot (JPG/PNG). Gemini OCR extracts the employee × day × shift grid. Tool renders the extracted schedule in the standard editable schedule table for the entity. User reviews, edits, approves. Existing Excel upload stays as fallback.

## Why
Today: screenshot → external Claude session → Excel → download → upload to tool. Multi-tool round-trip that the tool can do in one step, since the OCR pipeline for timecards already exists.

## Where in UI
Tab 1 (Schedules), per-entity section. New "Extract from screenshot" area (drag-drop, paste, file picker) alongside the existing Excel upload.

## Touches
ocr, schedules, display, import

## Risk
Medium — reuses the entire OCR call chain (`callGeminiVisionJson` extracted from the existing timecard OCR), so the only genuinely new artifacts are the prompt, the JSON→schedule mapping, and the intake UI.

## Reversibility
Reversible — feature added, no existing behavior changed. Excel upload path preserved.

## Definition of Done
Shipped as specified. 73/73 tests passing (63 pre-existing + 10 new).

## Out of scope
Multi-week schedules in one image. Handwriting-only schedules (best-effort). Non-Gemini backends. Auto-approval without review.

## Assumptions
1. Same Gemini model selection as timecards.
2. Same 12s retry delay, 3-attempt max.
3. Extracted schedule replaces existing after `confirm()` prompt.
4. Warnings from OCR shown as post-extraction toast.
5. Multi-week images: only first week extracted.
