# FC-00015 — Colored PDF export mirroring Excel

**Date:** 2026-09-01 · **Slice:** M · **Risk:** Medium · **Status:** done · **Affected entities:** All

## What
PDF exports (Combined, Cash-Only, Deposit-Only) come out with the exact same layout and colors as Excel exports. Uses the resolved palette from `_paletteForEntity(ent)`, so both hardcoded defaults and user-selected FC-00014 presets flow through.

## Why
Excel exports carry colors (FC-00012/FC-00014); PDF exports were monochrome. Inconsistent visual identity between the two formats.

## Where in UI
No UI change. Existing PDF buttons produce colored output.

## Touches
exports

## Risk
Medium — jsPDF+autoTable's cell-fill support is used via the `didParseCell` hook.

## Reversibility
Fully reversible via one revert commit.

## Definition of Done
Shipped as specified. 63/63 tests passing (57 pre-existing + 6 new).

## Out of scope
PDF-only print settings. Embedded fonts. Digital signing. Colored Timecard PDF export (kept uncolored, mirrors Excel scope).

## Assumptions
1. Same palette resolution as Excel: via `_paletteForEntity(ent)`.
2. Row types get their fill: header→palette header, body→palette body (Cash column → palette cash), subtotal→palette subtotal + bold, grand→palette grand + bold.
3. `pageBreak:'avoid'` on subtotal/grand rows so they stay with their entity.
4. Approximate Excel column widths converted to PDF points.
5. `_argbToRgbTriplet(argb)` helper converts `'FFAABBCC'` → `[0xAA,0xBB,0xCC]` (autoTable ignores alpha).
